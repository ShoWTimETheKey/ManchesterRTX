# ManchesterRTX 技术说明

项目概览、下载与编译见仓库首页的 [README](../README.zh-CN.md)。本文记录各部分的设计细节与实现取舍。

曼彻斯特城区体素模型的本地路径追踪版本，基于 OpenStreetMap 的真实街道与建筑布局。

- 渲染：NVIDIA RTX Path Tracing (RTXPT) 1.8.1。
- DLSS：Streamline 2.14.16 / DLSS 310.9.16，包括超分辨率 SR、光线重建 RR（预设 F）、多帧生成 MFG（预设 B：界面重组合）与 Reflex。

## 打开

双击 **`ManchesterRTX.exe`**。启动画面显示约 20 秒，模型为 1.4 GB。

载入期间，渲染窗口始终盖着一层深色幕布，等这些步骤都完成后幕布才淡出、城市淡入：
- 场景载入；
- 窗灯等材质到位；
- 自动曝光适应；
- 帧生成随窗口获得焦点后启动。

渲染窗口在创建时是隐藏的，等幕布已经画上屏幕才显示，所以启动画面周围不会闪出空白窗口。因此启动时不会看到空白窗口、占位颜色、灯光突然点亮或亮度跳动。随后镜头缓缓降到全景机位。

再次双击会把已打开的窗口切回前台，不会启动第二个。

**主题色与细节**

- 玻璃上的填充、分隔线、轨道和键帽都是淡紫或深紫，而不是纯白或纯黑，不会把紫色玻璃冲成灰色。
- 悬停高亮约 70 毫秒内淡入淡出，不会突然出现。
- 工具提示统一为深紫色小胶囊，悬停约半秒后从控件下方（底部坞上方）浮现，快捷键用次级色单独排在右侧。
- 编号徽章和选中的说明文字用等线粗体，与正文同一字族；时钟与标题字标用 Bahnschrift。
- 侧栏与列表内项目的圆角与外框同心。

**主题色**

- 面板是带紫色烟熏的磨砂玻璃。背景亮度先被限制在界面白色以内，再压进一个较暗的区间；紫色按玻璃自身的亮度着色，不会让玻璃变暗或变亮。所以无论在正午的白色天空前、HDR 下几倍于白色的天空前，还是夜里，面板都是同样深邃的紫色烟熏玻璃，而不是一块灰色遮罩。玻璃不再投射外阴影：阴影在 HDR 的 PQ 编码中混合时会显得过重，像一圈灰色光晕。
- 选中项的玻璃镜片是明亮的紫色。
- 金色用于当前状态：编号徽章、选中的图标、滑块、开关、开启中的漫游和雨天按钮，金色上的文字为深紫。
- 提示框、地标名牌和启动幕布也换成深紫色调。

**玻璃材质**

- 背后画面经两级模糊（宽约 45 像素）后，再经边缘的透镜弯折和轻微色散。
- 玻璃下的亮度被压在一个窄而暗的范围里，白字在天空、阳光下的石材和夜里的灯光前都清晰。
- 颜色保留适度的鲜艳度。
- 高光随鼠标方向变化：边缘有一圈细亮线，朝光一侧有主高光，另一侧有较弱的内反射。
- 阴影柔和宽阔，相邻的玻璃靠近时会融合。
- 玻璃与界面内容在同一帧绘制，滑动的面板不再拖着上一帧的玻璃。

**文字**

- 中文用等线（DengXian），字号整体加大。
- 文字分三级灰度（主、次、三级），带一层很淡的阴影。

**提示与弹窗**

- 提示像灵动岛一样从顶部中央弹出。
- 退出确认是 iOS 式提示框：标题和说明居中，下方是以细线分隔的“取消 / 退出”。

**其他**

- **退出**：点右上角电源按钮，或按 Esc（没有面板打开时），会弹出确认框。按 Enter 或点“退出”关闭；按 Esc 或点“取消”返回。
- **照片模式（P）**：切换到参考级路径追踪。镜头静止时逐帧累积 1024 次采样，云和时间也会暂停；得到无噪点画面后可“保存照片”。
- **界面合成与帧生成一致**：界面先在线性光下绘制，再按显示器的编码（SDR 为 sRGB，HDR 为 PQ）编码一次，并以与 DLSS 帧生成相同的方式叠在原始画面上。因此插出来的帧和真正渲染的帧上，半透明部分完全一样，不会在两者之间闪烁。
- **截图（F12）**：保存不含界面的 4K PNG 到 `captures\`。HDR 输出时保存的是同一帧的 SDR 版本。
- **沉浸模式（H）**：隐藏全部界面，包括地标；再按一次 H 恢复。
- 所有设置（含晴雨、HDR 与玻璃透明度）自动保存在 `renderer\bin\ManchesterRTX.ini`，下次打开时沿用。

## DLSS

| 项目 | 设置 |
|---|---|
| DLSS 模型 | `nvngx_dlss.dll`、`nvngx_dlssd.dll`、`nvngx_dlssg.dll` 均为 310.9.16，随 Streamline 2.14.16 SDK 提供 |
| 光线重建（RR） | Transformer 预设 F（`DLSSDPreset::ePresetF`），日志中显示为 `preset 6` |
| 多帧生成（FG） | 预设 B：界面重组合（`enableUserInterfaceRecomposition`）。渲染器把不含界面的画面（HUD-less）和预乘透明度的界面层（UI Color and Alpha）分别交给 DLSS-G；插帧只作用于城市画面，玻璃界面和文字逐帧重新合成，因此不会拖影 |
| 超分辨率（SR） | 使用 310.9.16 的默认预设（Transformer） |

Streamline 2.14 起，帧生成要求窗口处于前台；窗口在后台时自动退回单帧呈现，点回窗口即恢复。

## 光影与大气

**一天中的时刻。** 每种天气都是模型日期（7 月 26 日，英国夏令时）里的一个时刻，再加上一种天空状态。

所有天气都用同一套 RTXPT 物理大气天空（预计算的大气散射与体积云），太阳位置按曼彻斯特（北纬 53.48°）的真实太阳轨迹由时刻算出（NOAA 简化公式）。天空颜色、太阳光色和天光都由同一套大气计算得出，所以三者始终一致。

| 天气 | 时刻 | 太阳 | 天空 |
|---|---|---|---|
| 正午 | 12:00 | 高约 53°，东南偏南 | 碎云，云影掠过城市 |
| 午后 | 17:30 | 高约 31°，偏西 | 碎云，低斜阳光，长影与光束 |
| 多云 | 15:00 | 高约 50° | 厚云层几乎遮住太阳，柔和漫射光 |
| 黄昏 | 20:35 | 高约 4°，西北偏西（Deansgate 视角正好逆光） | 金色时刻，华灯初上 |
| 夜晚 | 23:30 | 地平线下约 14° | 北方天际残留的暮光、城市光污染、星空、月光 |

**延时摄影过渡。** 切换天气不是淡入淡出，而是一段 2–5 秒的延时摄影：
- 时钟沿较短的方向走到新时刻（夜晚到正午会经过日出），太阳沿真实轨迹移动，钟楼指针随之转动。
- 云层增厚或散去，雾霭、调色和曝光随之变化。
- 窗灯、路灯渐亮或渐暗，月光与湿润程度也一起过渡。
- 晴雨切换同样是约 3 秒的连续过渡。

**更顺滑的切换。** 所有天气共用一个天空，不再从磁盘载入天空贴图，切换时不再卡顿。
- 云每帧连续飘动（约 12 m/s），不再每 0.25 秒跳一步。
- 窗灯等光源始终留在 RTXPT 的光源列表里，只改变亮度，光源采样的历史不会重建。

**夜空与雨天。**
- 夜空：地平线附近是城市光污染的暖色辉光，往上渐变为深蓝黑，云底映着城市灯光。
- 星星由大气合成通道逐像素绘制，任何视角下都是锐利的小点。它们会被云遮住，靠近地平线时被辉光淹没。
- 雨天：厚云层吞没太阳，光线变暗变冷，雾更浓；夜里云底被城市照亮。

**色阶与闪烁。**
- 天空立方体贴图不再做 BC6H 压缩（它会让平滑的天空渐变出现台阶）。
- 最终画面在量化前加了逐帧变化的三角分布抖动（SDR 为 8 位 sRGB，HDR10 为 10 位 PQ）。天空、雾霭和夜色的渐变因此没有色阶断层；玻璃界面在 SDR 下同样抖动。
- 大气体积光的时间累积加长，光柱和雾霭稳定，不再闪动。
- **转动镜头时的背景闪烁**：大气通道原先用世界坐标的逆投影矩阵求每个像素的视线。近裁剪面只有 0.25 m，城市坐标却有几千米，浮点舍入让每条视线偏离约一个像素，而且偏离的样子随相机位置变化。于是雾霭边缘、云影和星星对不准下面的画面，镜头一动就闪。现在视线用只含旋转与投影的相对相机矩阵求得，与画面逐像素对齐。
- **历史在运动中不再丢失**：重投影时，原先把历史深度与当前相机的距离比较，镜头前进时几乎处处判为“不是同一表面”，雾霭每帧从头采样。现在与上一帧相机到同一点的距离比较；天空按方向重投影（没有视差误差）；新露出的区域用加倍步数先采样，再按运行平均几帧内收敛。
- **轮廓超采样**：建筑与天空交界处的像素用 8 条子像素视线合成雾霭，边缘与 DLSS 抗锯齿后的画面一样平滑，镜头移动时不再爬动锯齿。
- **云影**：改在四分之一分辨率下计算并做时间累积，取代逐像素的二值阴影测试，阴影边缘不再出现随镜头爬动的锯齿。
- **星星**：每颗星铺开约一个半像素。原先比像素还小，随镜头转动在亮与暗之间跳变。

**摩尔纹。** RTXPT 默认的纹理 LOD 偏移是 −1，再加上 DLSS 的 −0.4，细砖缝、石缝和窗格因此采样过锐，产生摩尔纹。现在总偏移约为 −0.15：纹理依旧清晰，但不再出现摩尔纹。

**自动曝光像人眼一样适应**：在对数空间里平滑跟随画面的平均亮度，变亮比变暗略快。不再每帧跳动，所以亮天空或灯光进出画面时不会闪烁。

**运动的节奏。** 镜头飞行、开场滑行、WASD 移动和延时摄影都按平滑后的帧时间推进（约十帧的滑动平均）。开启帧生成后，驱动以均匀节奏显示帧，但程序循环自身的帧间隔会周期性波动（实测 4× 帧生成时为 16 / 21 / 27 ms 循环）。直接用原始间隔推进镜头，每个显示帧的位移忽大忽小，大幅转动时就会抖动。偶发的长帧（载入、显存换页）超过 0.15 秒的部分会被截掉：镜头在那一刻停顿，而不是跳一大步。

**光线追踪大气**（`Manchester\Atmosphere.hlsl`，在 DLSS 光线重建之后、泛光与色调映射之前作用于 HDR 画面）：

- **体积光。** 以四分之一分辨率逐像素沿视线步进 24 步，步点靠近相机处更密。每一步向太阳发出一条阴影光线，穿过整座城市的加速结构，所以塔楼、高架和树木都会在雾霭中切出真实的光柱与阴影体积。
- **雾霭。** 按高度指数衰减，散射采用 Henyey-Greenstein 前向散射，面向太阳时最亮。远处建筑逐渐融入大气（空气透视）。
- **云影。** 取自天空自身的云场：云的影子在城市地面和空气中缓缓移动，与天上的云一一对应。
- **时间累积。** 步进抖动逐帧变化，取最近至多 15 帧的运行平均，带重投影：同一表面才沿用历史，天空按方向重投影。
- **高度自适应。** 相机升高时雾霭自动变薄，所以全景鸟瞰仍然通透。
- **雨天。** 雾更浓，光束减弱，没有云影。

**材质。** 玻璃幕墙、窗户、店面玻璃按金属度与反射色调设为镀膜反射玻璃（深蓝、蓝绿、银灰等），路径追踪下会映出天空、阳光和相邻建筑。

**色调与调色。**
- ACES 电影色调曲线。
- 每种天气各自设定饱和度、对比度、暗角、白平衡与泛光强度和半径（`manchester.app.json` 的 `time` / `sky` / `haze` / `grade`，由 `export2.mjs` 的 `LIGHT` 表生成）。
- 黄昏的窗灯和钟面亮度相应降低，不会压过天空和指针。

## HDR

Windows 开启 HDR 时，应用以 **HDR10** 输出：10 位、PQ（SMPTE ST 2084）、BT.2020。DLSS 帧生成支持这一格式。

- **色调曲线**：同一条 ACES 曲线，肩部从 SDR 白抬到显示器峰值。暗部和中间调与 SDR 画面一致；阳光下的石材、太阳附近的天空、窗灯和玻璃上的高光则保留亮度，不再被压平。
- **亮度设定**：
  - 显示器峰值读取 Windows（包括“HDR 校准”配置）报告的值；
  - 白色亮度（即 SDR 白和界面亮度）跟随 Windows 的“SDR 内容亮度”，但不超过峰值的 40%，为高光留出余量。
  - 本机显示器报告峰值 600 尼特、SDR 白 480 尼特，因此白色亮度为 240 尼特。
  - 白色亮度与峰值都可以在设置里手动调。
- **界面**：液态玻璃与文字在线性光下合成，再按 PQ 编码，交给 DLSS 帧生成的界面重组合。
- **截图**：仍保存为 SDR PNG，由同一帧另行按 SDR 色调映射得到。
- **开关**：设置 → 显示 → HDR 输出。改动在重新打开后生效。
- **验证**（开发者）：F8 把送往显示器的原始帧存为 `captures\raw-hdr10.png`，`tools\pq-view.ps1 -In captures\raw-hdr10.png -Out x.png -Raw -Stats` 会解码并列出亮度分布（尼特）。

**F7 调试视图**（循环切换，屏幕上会提示当前编号）：
1. 仅散射光；
2. 阳光照度（上半屏）与天光（下半屏）；
3. 地表云影系数；
4. 地表阳光可见性；
5. 大气的时间历史：白色表示已累积满，黑色表示刚开始累积；红色是做了超采样的轮廓像素；
0. 正常画面。

**开发者：闪烁与卡顿的测量。**
- **F9**：录制接下来 48 帧，在色调映射之后、界面之前存为 SDR 的 `captures\rec-NN.bmp`，同时写出 `captures\rec.csv`（帧时间、原始帧时间、相机、帧生成倍数、窗口焦点）。帧数据先复制到系统内存，所以录制本身不占显存。
- **F10**：只记录 400 帧的帧时间。
- **环境变量**：
  - `MRTX_RECORD_STARTUP=N`：录下开场滑行的 N 帧；N 为负数时只记帧时间。
  - `MRTX_RECORD_DT=21.7`：录制期间镜头每帧固定前进 21.7 ms，不同设置的两次录制因此逐帧对应。
- **工具**：
  - `tools\rec-run.ps1`：直接启动引擎，录下开场滑行，并把帧移到单独的文件夹；
  - `tools\rec-view.ps1 -Flicker`：输出闪烁热图，取每个像素的二阶时间差，匀速运动与缓慢变化会相互抵消，只剩闪烁；
  - `tools\rec-view.ps1 -Crop`：把连续几帧的同一区域排成一行对比；
  - `tools\rec-region.ps1`：输出某一区域每帧的平均亮度及其跳动；
  - `tools\screen-rec.ps1`：用机器上现成的 ffmpeg（ddagrab，桌面复制）录下显示器实际显示的帧（包括帧生成插出的帧），列出哪些是新帧、每帧变化多少，并输出一排连续帧。

## 对 RTXPT / Donut 的修改（均标有 `ManchesterRTX` 注释）

- 应用模式 `--app`：中文界面（等线 / Bahnschrift / Segoe Fluent Icons）、无边框全屏、设置持久化、启动完成信号、不弹 RTXPT 进度窗口。
- HDR10 输出：
  - Donut 的 DX12 交换链支持 `hdr10ColorSpace`（R10G10B10A2 + ST 2084 / BT.2020）；
  - 启动时读取显示器的 HDR 状态、亮度范围与 SDR 白（`QueryDisplayHdr`）；
  - LDR 画面与 HUD-less 缓冲在 HDR 下为 R10G10B10A2；
  - 色调映射新增 HDR10 输出、自动曝光的时间适应，以及供截图用的 SDR 二次映射（`RenderSDR`）。
- 程序化天空：太阳在云前的比例可连续变化，另有夜空（光污染辉光、云底辉光）。
- Streamline 2.14.16：
  - 光线重建预设 F；
  - DLSS-G 的 `enableUserInterfaceRecomposition`；
  - 新增 HUD-less 与 UI Color and Alpha 资源标记（`TagResourcesHudlessAndUI`）。
- ImGui 渲染改为预乘透明度输出，界面先画进单独的层，再由液态玻璃着色器合成。
- 新增命令行参数 `--dlssMode`、`--dlssFG`、`--renderUnfocused`、`--app`。
- Donut：字体支持自定义字形范围；窗口创建时即读取 DPI 缩放。
- 读取场景文件中环境光的色调与旋转。
- 程序化天空（`SampleProceduralSky`）：
  - 应用通过 `g_ProceduralSkyOverride` 控制太阳方向、云量、云的流动与亮度；
  - 太阳可以画在云层之上。
- `Sample::PostProcessPreToneMapping` 在泛光之前调用光线追踪大气（`ManchesterAtmosphere`，用内联 RayQuery 查询场景的顶层加速结构）。

- 日志输出到 stdout，DLSS 与帧生成状态变化时记录一行。
- `Sample::Animate` 把平滑后的帧时间（`ManchesterApp::SmoothFrameTime`）交给相机与场景动画。`Sample::Render` 在色调映射后为开发者录制复制 SDR 帧（F9）。

## 已知限制

- 普通建筑为 0.6 m 体素，OSM 缺少高度的建筑按类型估算。轮廓有斜边的普通建筑，斜边处呈阶梯状，不开窗。
- Acer 各体块的层数、River Street Tower 的立面分格，以及各钟塔、尖顶的高度，按公开描述与照片近似，并非测绘数据。
- 两座球场为距离压缩后的卫星模型；老特拉福德的屋顶为简化形式。
- 帧生成的插帧只显示在屏幕上；截图保存的是渲染帧。
- 远处夜景里比像素还小的窗灯，在镜头运动时仍会轻微闪烁；雨夜湿地面上灯光的反光，也会在相邻几帧间轻微明暗变化。这是光线重建以每像素 1 个样本重建亚像素光源与光泽反射时的残余噪声。把光源采样从 NEE-AT 换成按功率采样，实测几乎没有差别，所以保留了默认设置。
- 帧生成的界面重组合按渲染帧更新界面，所以玻璃面板里透出的背景以渲染帧率变化，城市画面则以显示帧率变化。
